## L'essentiel

Quatre règles protègent votre projet. Claude les applique sans que vous le demandiez.

<SecurityRules />

## À essayer

**1. Vérifiez que vos clés sont à l'abri.**

<PromptCopy>Vérifie qu'aucune clé ni aucun mot de passe ne se trouve dans le code ou sur GitHub.</PromptCopy>

**2. Avant de partager votre lien largement, faites relire le projet.**

<PromptCopy>Relis mon projet comme le ferait un attaquant et corrige le point le plus grave.</PromptCopy>

<AttackerReview />

## Comprendre

<div class="idea">
  <div>
    <h3>Une clé ne va jamais dans le code</h3>
    <p>Une clé API est un mot de passe : elle permet à votre projet d'utiliser un service, souvent payant. Elle ne va ni dans le code, ni sur GitHub.</p>

### Si une clé a fui

Changez-la tout de suite, sur le site qui vous l'a donnée. L'effacer du code ne suffit pas : elle reste dans l'historique.

<details class="hint">
  <summary>Pour aller plus loin</summary>
  <p><strong>Ne collez jamais une clé dans la conversation.</strong> Demandez à Claude où la ranger : il vous indique le fichier, et vous l'y collez vous-même. Le pas à pas est dans le <a href="/faq/cle-api/">guide de la clé API</a>.</p>
  <p><strong>Une clé pour le site en ligne.</strong> Vercel a sa propre page pour ranger les clés d'un projet en ligne. Demandez à Claude de vous y conduire.</p>
  <p><strong>Les règles 2 à 4</strong> ne comptent que si votre projet reçoit des visiteurs : une page qui s'affiche sans rien demander ni rien enregistrer court peu de risques.</p>
  <p>Documentation officielle : <a href="https://docs.github.com/fr/code-security/getting-started/best-practices-for-preventing-data-leaks-in-your-organization">éviter les fuites de données sur GitHub</a>, <a href="https://vercel.com/docs/environment-variables">les variables d'environnement sur Vercel</a>.</p>
</details>

<details class="hint">
  <summary>Notes formateur</summary>
  <p><strong>Démonstration en direct, cinq minutes.</strong> Ouvrez le <code>CLAUDE.md</code> d'un projet cadré avec <code>setup-projet</code> et montrez le bloc Sécurité. Puis lancez la relecture « comme un attaquant » sur le projet de démonstration et lisez le résultat avec le groupe.</p>
  <p><strong>À marteler.</strong> Une seule règle à retenir par cœur : une clé ne va ni dans le code, ni sur GitHub, ni dans la conversation. Les trois autres, Claude les porte.</p>
  <p><strong>Pièges fréquents.</strong> Une clé collée dans la conversation pour aller plus vite : la faire changer aussitôt. Une personne inquiète pour une simple page vitrine : la rassurer, le risque arrive avec les formulaires, les comptes et les services payants.</p>
</details>
