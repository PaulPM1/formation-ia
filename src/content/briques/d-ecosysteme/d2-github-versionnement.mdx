## L'essentiel

GitHub garde une copie de votre projet et tout son historique. C'est Claude qui sauvegarde : vous le lui demandez.

<SaveToGitHub />

## À essayer

**1. Sauvegardez, dès que quelque chose marche.**

<PromptCopy>Sauvegarde mon projet sur GitHub.</PromptCopy>

**2. Regardez votre historique.**

<PromptCopy>Montre-moi la liste de mes sauvegardes, de la plus récente à la plus ancienne.</PromptCopy>

**3. Le jour où un changement casse tout, revenez en arrière.**

<PromptCopy>Ce changement a tout cassé. Reviens à la dernière sauvegarde qui marchait.</PromptCopy>

## Comprendre

### Chaque sauvegarde est un point de retour

<details class="hint">
  <summary>Pour aller plus loin</summary>
  <p><strong>Les mots que Claude emploiera.</strong> Un <em>dépôt</em> est l'espace de votre projet sur GitHub. Un <em>commit</em> est une sauvegarde nommée. <em>Pousser</em>, c'est envoyer vos sauvegardes sur GitHub.</p>
  <p><strong>La première fois.</strong> Claude crée lui-même le dépôt sur votre compte GitHub. Vous pouvez ensuite ouvrir github.com et y voir votre projet.</p>
  <p><strong>À plusieurs.</strong> GitHub sert aussi à travailler à plusieurs sur un même projet, avec des branches et des pull requests. Vous n'en avez pas besoin pour construire seul.</p>
  <p>Documentation officielle : <a href="https://docs.github.com/fr/get-started/start-your-journey/about-github-and-git">À propos de GitHub et de Git</a>.</p>
</details>

<details class="hint">
  <summary>Notes formateur</summary>
  <p><strong>Démonstration en direct, cinq minutes.</strong> Sur le projet de démonstration, demandez « sauvegarde mon projet sur GitHub », puis ouvrez github.com : le projet y est. Cassez volontairement la page (« supprime tout le style »), montrez l'aperçu abîmé, puis demandez le retour en arrière.</p>
  <p><strong>À faire voir.</strong> La liste des sauvegardes sur github.com, avec leurs noms. C'est la preuve que rien n'est perdu.</p>
  <p><strong>Pièges fréquents.</strong> Une personne qui enchaîne dix changements sans sauvegarder : le retour en arrière l'emmènera trop loin. La règle à répéter : ça marche, on sauvegarde. Si l'envoi est refusé, la connexion GitHub n'a pas abouti : voir la brique D2-bis.</p>
</details>
