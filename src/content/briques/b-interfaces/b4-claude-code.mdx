## Cap

**Objectif facultatif :** réaliser en 20 minutes une modification limitée et prouvée dans la mini-page du kit.

- 2 minutes : contexte du dossier.
- 4 minutes : boucle I.P.M.T.R.
- 10 minutes : mission avec `prompts/04-claude-code.md`.
- 4 minutes : page, test et diff.

VS Code, Node et Claude Code doivent déjà fonctionner. Toute installation utilise B4-bis ou se termine hors chrono.

## Concept durable

Claude Code travaille dans le contexte réel d’un dossier. La boucle **I.P.M.T.R.** borne son action :

1. **Inspecter** `brief.mjs`, `app.mjs` et `brief.test.mjs` sans écrire.
2. **Planifier** trois étapes maximum et attendre l’accord.
3. **Modifier** uniquement le rendu de la source et le test associé.
4. **Tester** avec `node --test`.
5. **Relire** le diff inline dans VS Code avant d’accepter.

La page fonctionne déjà et trie les six cartes. La propriété `source` existe dans les données mais n’est pas affichée. Toute refonte, nouvelle dépendance ou modification du tri dépasse la mission.

## Pratique avec Claude

Ouvrez `kits/bloc-b-assistant/code/` dans VS Code. Dans le terminal intégré :

```sh
node --test
```

Le test de tri passe et un test source est marqué TODO. Ouvrez ensuite Claude Code dans VS Code et copiez `kits/bloc-b-assistant/prompts/04-claude-code.md`.

## Mission commune

1. Demandez l’inspection sans modification.
2. Relisez le plan de trois étapes maximum.
3. Refusez toute refonte, dépendance ou changement hors `code/`.
4. Approuvez uniquement l’ajout de la source et la complétion du test.
5. Laissez Claude Code exécuter `node --test`.
6. Ouvrez la page et vérifiez une source sous chaque carte.
7. Relisez le diff inline dans VS Code, ligne par ligne.

## Critères de réussite

- Chaque carte affiche son chemin source.
- Le tri initial reste `N01, N06, N03, N05, N02, N04`.
- Le test TODO est remplacé par une assertion réelle.
- `node --test` passe sans TODO.
- Le diff ne contient aucune modification étrangère à la source et au test.

## Livrable

Le plan approuvé, la sortie de `node --test`, une page montrant les sources et le diff relu dans VS Code.

## Notes formateur

- De 00:00 à 02:00 : ouvrir `code/README.md` et lancer le test initial.
- De 02:00 à 06:00 : parcourir I.P.M.T.R. et ses trois portes.
- De 06:00 à 16:00 : ouvrir `prompts/04-claude-code.md`, inspecter, approuver et modifier.
- Couper la génération à 16:00 dans B4.
- De 16:00 à 20:00 : vérifier la page, relancer `node --test` et relire le diff inline.
- Repli : utiliser `kits/bloc-b-assistant-formateur/corriges/claude-code.patch`, puis conserver le test et le diff en direct.

## Défis avancés

- Demander à Claude Code d’expliquer pourquoi le tri reste inchangé.
- Ajouter un cas de test qui vérifie les trois chemins de source sans figer tout le HTML.

## Variantes

- **Claude Code indisponible :** appliquer le patch formateur et faire auditer le diff.
- **Sans serveur :** tester le HTML généré avec `renderBrief(notes)` et conserver `node --test` comme preuve.
- **Temps court :** le formateur modifie, les participants approuvent ou refusent chaque étape.

## Dépannage

- **Le test échoue avant modification :** arrêter et utiliser B4-bis ; ne pas attribuer cet échec au changement.
- **Le plan refactorise la page :** demander une réduction à deux fichiers et une responsabilité.
- **Le tri change :** revenir à l’état initial et restaurer le test d’ordre avant de reprendre.
- **Le diff est trop large :** refuser, annuler et reformuler l’objectif unique.
