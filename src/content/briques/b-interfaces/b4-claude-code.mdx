## Cap

**Objectif :** comprendre comment collaborer avec un agent de code dans un vrai dossier de projet.

- Durée cible : 20 minutes.
- Prérequis : A2, A4 et un projet de démonstration fourni par le formateur.
- Résultat attendu : une modification limitée, un test exécuté et un diff relu.

L'installation est préparée ou vérifiée séparément. Si Claude Code n'est pas disponible sur un poste, le participant suit la démonstration en binôme et réalise l'audit du plan et du diff.

## Concept durable

Claude Code travaille depuis le terminal dans le contexte d'un dossier. Il peut lire des fichiers, rechercher dans le projet, proposer un plan, modifier du code et exécuter des commandes. Cette capacité ne remplace pas la méthode ; elle la rend indispensable.

Utilisez la boucle **I.P.M.T.R.** :

1. **Inspecter** le projet et les règles avant de demander une modification.
2. **Planifier** une petite étape et définir le résultat attendu.
3. **Modifier** uniquement les fichiers nécessaires.
4. **Tester** avec une commande ou un scénario indépendant.
5. **Relire** le diff avant de conserver, committer ou partager.

Commencez en lecture et en planification. Une commande proposée peut avoir des effets au-delà du code : supprimer des fichiers, installer un paquet, contacter un service ou publier. Lisez la commande et son périmètre avant de l'autoriser.

## Pratique avec Claude

Depuis le terminal ouvert dans le projet de démonstration :

```bash
claude
```

Commencez par une demande sans écriture :

```text
Inspecte ce projet sans modifier de fichier. Explique son objectif, indique la
commande de test existante et propose un plan minimal pour remplacer le titre
de la page par « Mon premier chantier IA ».
```

Après lecture du plan :

```text
Applique uniquement cette modification. Lance le test existant, puis résume les
fichiers modifiés et ce que je dois vérifier moi-même. N'ajoute aucune dépendance.
```

À la fin, quittez ou ouvrez un second terminal et inspectez le diff avec l'outil Git du projet.

## Mission commune

Dans une copie du projet fourni :

1. demandez une cartographie en lecture seule ;
2. choisissez une modification visible d'une seule responsabilité ;
3. faites produire un plan de trois étapes maximum ;
4. autorisez uniquement les actions comprises ;
5. lancez le test prévu ;
6. relisez chaque ligne du diff ;
7. acceptez, corrigez ou annulez la modification.

**Critère de réussite :** le changement visible correspond à la demande, le test passe et aucune modification étrangère n'apparaît dans le diff.

## Livrable

Le prompt initial, le plan validé, la sortie du test et le diff final. Un commit est facultatif à ce stade ; le versionnement sera approfondi dans la famille D.

## Notes formateur

- Utiliser un dépôt jetable avec un test rapide et un changement évident.
- Verbaliser chaque permission : ce que la commande lit, écrit ou contacte.
- Montrer qu'il est légitime de refuser une commande et de demander une alternative.
- Ne pas terminer sur le résumé de Claude : ouvrir le fichier, exécuter le test et lire le diff.

Transition : pour se repérer dans un projet et utiliser un terminal confortablement, nous allons valider l'installation de VS Code.

## Défis avancés

- Demandez deux plans concurrents et choisissez le plus petit diff.
- Ajoutez un test qui décrit le comportement avant la modification.
- Faites expliquer une ligne du diff et demandez ce qui pourrait casser ailleurs.

## Variantes

- **Claude Code indisponible :** le formateur pilote ; les participants votent sur chaque permission et auditent le diff imprimé.
- **Sans Git :** comparez une copie avant/après avec l'éditeur, sans prétendre remplacer le versionnement.
- **Public développeur :** utiliser le mode plan, les tests ciblés et une branche jetable.

## Dépannage

- **`claude` est introuvable :** consulter le guide d'installation officiel et vérifier le terminal utilisé ; ne pas lancer une commande copiée d'une source non fiable.
- **Claude ne voit pas le bon projet :** arrêter, vérifier le dossier courant avec `pwd` sur macOS/Linux ou `Get-Location` dans PowerShell, puis relancer au bon endroit.
- **Une commande semble risquée :** refuser, demander son effet exact et une option en lecture seule.
- **Le test échoue avant la modification :** noter l'état initial et ne pas attribuer cet échec au changement.

## Ouverture

Claude Code agit dans un projet ; VS Code fournit une vue durable du dossier, des fichiers, du terminal et des changements à relire.

## Scénario de démonstration

Point de départ : une petite page affiche « Démonstration ». Le projet contient une commande de test qui vérifie le titre. Claude Code doit cartographier le projet, changer le titre demandé et mettre le test à jour seulement si le contrat le justifie.

Résultat visible : la page affiche le nouveau titre, la commande de test réussit et le diff ne contient que les fichiers attendus.

## Déroulé de démonstration

1. Afficher l'état initial et lancer le test avant Claude Code.
2. Démarrer `claude`, puis demander une inspection sans écriture.
3. Relire le plan avec le groupe et préciser le critère de réussite.
4. Autoriser la petite modification ; refuser toute dépendance inutile.
5. Observer le test lancé par Claude.
6. Vérifier indépendamment la page et le diff.
7. Demander au groupe ce qu'il accepterait ou corrigerait avant un commit.
