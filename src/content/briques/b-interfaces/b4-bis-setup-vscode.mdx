## Cap

**Objectif de rattrapage :** corriger uniquement le maillon manquant sur un poste presque prêt.

- 3 minutes : diagnostiquer dossier, terminal ou extension.
- 4 minutes : aligner Explorateur, fichier et terminal.
- 3 minutes : exécuter le test et ouvrir Claude Code.

Une installation complète de VS Code, Node ou Claude Code ne tient pas dans cette piste. Elle se termine avant la séance ou hors chrono.

## Concept durable

Un workspace utile relie trois vues du même dossier :

- l’Explorateur montre `kits/bloc-b-assistant/code/` ;
- l’Éditeur ouvre un fichier de ce dossier ;
- le Terminal exécute les commandes depuis ce même chemin.

Le poste est prêt seulement si `node --test` passe à cet endroit et si le panneau Claude Code s’ouvre dans VS Code.

## Pratique avec Claude

Ouvrez `kits/bloc-b-assistant/code/` comme dossier dans VS Code, pas seulement `index.html`.

Dans le terminal intégré :

```sh
node --test
```

Ouvrez ensuite le panneau Claude Code et vérifiez qu’il utilise ce workspace. Aucune modification de la mini-page n’est demandée ici.

## Mission commune

1. Identifiez le seul maillon en échec : dossier, terminal Node ou extension.
2. Ouvrez `code/` dans l’Explorateur.
3. Ouvrez `brief.test.mjs` dans l’Éditeur.
4. Créez un nouveau terminal intégré.
5. Vérifiez le chemin courant.
6. Exécutez `node --test`.
7. Ouvrez le panneau Claude Code.

## Livrable

Trois preuves concordantes : chemin `kits/bloc-b-assistant/code`, test passant et panneau Claude Code ouvert.

## Notes formateur

- De 00:00 à 03:00 : diagnostiquer le maillon manquant.
- De 03:00 à 07:00 : ouvrir `code/` et réaligner le terminal.
- De 07:00 à 10:00 : exécuter `node --test` et ouvrir Claude Code.
- Couper B4-bis à 10:00 sans prolongation.
- Repli : placer le participant en observation sur un poste prêt ; terminer toute installation après le bloc.

## Défis avancés

- Ouvrir le dossier depuis le terminal avec `code .` si la commande existe déjà.
- Expliquer la différence entre un fichier ouvert et un workspace ouvert.

## Variantes

- **macOS ou Git Bash :** vérifier le chemin avec `pwd`.
- **Windows PowerShell :** vérifier le chemin avec `Get-Location`.
- **Commande `code` absente :** utiliser Fichier > Ouvrir le dossier ; cela ne bloque pas le checkpoint.

## Dépannage

- **Le test ne trouve aucun fichier :** fermer le terminal, rouvrir `code/` comme dossier et créer un nouveau terminal intégré.
- **Node est introuvable :** sortir du chrono et utiliser le poste observateur.
- **Claude Code ne s’ouvre pas :** vérifier l’extension déjà installée et la connexion ; ne lancer aucune installation longue.
- **Workspace Trust apparaît :** n’accorder la confiance qu’au kit fictif fourni et connu.

## Ouverture

Cette piste s’arrête au checkpoint. Revenez au sommaire ; ne naviguez pas automatiquement vers B4 ni C1.

## Diagnostic initial

Testez dans cet ordre : `code/` visible dans l’Explorateur, `node --test` disponible dans le terminal, panneau Claude Code ouvrable. Ne corrigez que le premier échec.

## Test final

Le setup passe lorsque le terminal affiche le chemin de `kits/bloc-b-assistant/code`, que `node --test` réussit et que Claude Code s’ouvre dans ce workspace.

## Dépannage Mac

- Utiliser `pwd` pour contrôler le dossier courant.
- Ouvrir le dossier depuis VS Code si `code .` n’est pas configuré.
- Si Node manque, ne pas installer pendant les dix minutes.

## Dépannage Windows

- Utiliser `Get-Location` dans PowerShell.
- Vérifier que le chemin se termine par `kits\bloc-b-assistant\code`.
- Si Node ou l’extension manque, basculer sur le poste observateur et terminer hors chrono.
