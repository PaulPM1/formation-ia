# À compléter avant la formation

Liste des éléments que seule une préparation réelle peut fournir. À traiter
pendant le build du prototype.

## Liens à renseigner

- **Adresse du dépôt modèle** dans `src/content/atelier/p1-naissance.mdx`,
  tâche 3, bloc `kit-link` : remplacer `[À COMPLÉTER : adresse du dépôt
  modèle]` et le `href` par l'adresse réelle une fois le dépôt publié et
  coché « Template repository » dans ses réglages.

## Captures d'écran à prendre

Les moments où une image vaut mieux qu'un paragraphe. À capturer pendant le
build, en résolution lisible sur vidéoprojecteur, puis à déposer dans
`public/atelier/` et à insérer dans les blocs repliables correspondants.

- [ ] Le bouton **Use this template** sur la page du dépôt modèle, avec le
      menu déroulant ouvert sur « Create a new repository ».
- [ ] Le formulaire de création du dépôt : champ du nom, choix Public ou
      Private.
- [ ] La page du dépôt personnel obtenu, en montrant que le nom en haut de
      page a changé.
- [ ] La barre d'adresse du navigateur, pour montrer quoi copier.
- [ ] La page d'autorisation GitHub qui s'ouvre pendant l'authentification.
- [ ] L'écran Vercel avec le bouton **Continue with GitHub**.
- [ ] L'écran d'autorisation Vercel qui demande l'accès aux dépôts.
- [ ] L'arborescence du kit ouverte dans VS Code, panneau Explorateur
      visible.

## À valider pendant le build

- [ ] Le temps réel de la tâche 2 (comptes) et de la tâche 3 (dépôt) :
      décider si les comptes doivent être créés avant l'arrivée.
- [ ] Le prompt d'authentification GitHub fonctionne-t-il tel quel sur Mac
      et sur Windows ?
- [ ] La formulation « remonte le contenu de la variante à la racine » est
      elle comprise et exécutée correctement par Claude ?
