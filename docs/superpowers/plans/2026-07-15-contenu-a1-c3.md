# Contenu pédagogique A1 à C3 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transformer les 14 gabarits MDX de A1 à C3 en briques pédagogiques complètes, prêtes à animer et à relire.

**Architecture:** Le modèle de contenu, les routes et le design restent inchangés. La rédaction est livrée en trois lots cohérents — concepts A, interfaces B, extensions C — protégés par un contrat éditorial automatisé qui distingue les 14 briques rédigées des 10 gabarits D à F encore vides.

**Tech Stack:** Astro 7, MDX, TypeScript 7, `node:test`, `gray-matter`.

## Global Constraints

- Modifier uniquement les 14 briques A1–C3, le test d'inventaire et ce plan.
- Conserver toutes les rubriques MDX obligatoires et l'ordre pédagogique existant.
- Passer les 14 briques à `status: a-relire`, renseigner `learningObjective` et `expectedOutcome`, conserver `owner: a-attribuer`.
- Écrire pour des adultes débutants, avec des défis facultatifs pour les participants rapides.
- Chaque mission doit être faisable isolément avec un résultat et un critère de réussite observables.
- Ne jamais demander de secret, jeton, donnée client ou accès inutile.
- Ne pas figer de prix, quota ou emplacement d'interface susceptible d'évoluer ; lier les pages officielles qui font autorité.
- Sources produit à vérifier pendant la rédaction : [Artifacts](https://support.anthropic.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them), [Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork), [Claude Code](https://code.claude.com/docs/en/overview), [Skills](https://code.claude.com/docs/en/skills), [MCP](https://code.claude.com/docs/en/mcp), [hooks](https://code.claude.com/docs/en/hooks-guide), [tâches planifiées](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork), [limites d'usage](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work) et [VS Code](https://code.visualstudio.com/docs/getstarted/overview).

**Interfaces:**
- Consumes: `loadBrickDocuments()`, `hasVisibleEditorialContent()` et les métadonnées de `BrickDocumentInput`.
- Produces: une liste canonique `DRAFTED_BRICK_IDS` et des assertions qui empêchent le retour de gabarits vides dans A1–C3.

- [ ] **Step 1: Remplacer le test historique « tous les squelettes sont vides »**

Ajouter après `contentDirectory` :

```ts
const DRAFTED_BRICK_IDS = [
  'a1', 'a2', 'a3', 'a4', 'a5',
  'b0', 'b1', 'b2', 'b3', 'b4', 'b4-bis',
  'c1', 'c2', 'c3',
] as const;
```

Remplacer le test qui exige l'absence totale de contenu par :

```ts
test('les briques A1 à C3 sont rédigées et prêtes à relire', async () => {
  const documents = await loadBrickDocuments(contentDirectory);
  const drafted = documents.filter((document) =>
    DRAFTED_BRICK_IDS.includes(document.data.id as (typeof DRAFTED_BRICK_IDS)[number]),
  );

  assert.equal(drafted.length, DRAFTED_BRICK_IDS.length);
  for (const document of drafted) {
    assert.equal(document.data.status, 'a-relire', document.data.id);
    assert.equal(document.data.owner, 'a-attribuer', document.data.id);
    assert.ok(document.data.learningObjective, document.data.id);
    assert.ok(document.data.expectedOutcome, document.data.id);
    assert.equal(hasVisibleEditorialContent(document.body), true, document.data.id);
    assert.doesNotMatch(document.body, /\{\/\*[\s\S]*?\*\/\}/, document.data.id);
  }
});

test('les briques D1 à F2 restent des gabarits à rédiger', async () => {
  const documents = await loadBrickDocuments(contentDirectory);
  const remaining = documents.filter(
    (document) => !DRAFTED_BRICK_IDS.includes(
      document.data.id as (typeof DRAFTED_BRICK_IDS)[number],
    ),
  );

  assert.equal(remaining.length, 10);
  assert.equal(
    remaining.some((document) => hasVisibleEditorialContent(document.body)),
    false,
  );
});
```
